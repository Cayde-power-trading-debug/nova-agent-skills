## 1. 从原始价格到可计算标签

`price_data.py:312-391` 的 `parse_workbook` 扫描工作表表头，只接受可识别日期、市场（日前/实时）、`00:00`–`23:00` 的价格表；纵表走专用解析支路。日期缺失时仅在相邻市场配对或序号前后日期能唯一确定时恢复，无法唯一确定则隔离。24 时点有空值时标记 `incomplete_hours`；同日同市场重复且价格冲突时整体隔离该键。

核心条件（与源码保持语义一致）：

```python
values = [number(row[hours[h]]) for h in range(24)]
mean = sum(values) / 24 if all(v is not None for v in values) else None
key = (date, market)
if key in seen and seen[key]['hours'] != values:
    conflicts.add(key)  # 冲突键不能参与实际标签
```

`price_model.py:106` 的实际日前日均价只取 24 点齐全的 `da` 行。实际跨日变化为 `ΔP_actual = P̄_DA(T)−P̄_DA(B)`；所有价格、变化值单位为元/MWh。

## 2. 天气因子到预期价差

`price_model.py:187-247` 先把过去完整 30 天的天气按日汇总：降水取 24 小时总量，其余字段取日均。字段的样本标准差为 `std_j=max(sd_30d,j,1e−6)`。`price_signal_logic.py:58-90` 则使用冻结因子：

```text
z_j(T,B) = [W_j(T) − W_j(B)] / std_j
μ(T,B) = β0 + Σ_j β_j z_j(T,B)                  [元/MWh]
```

`D+1` 比较目标日 `T=D+1` 与起报日 `B=D`；`D+3…D+7` 比较 `T` 与 `B=T−3`。这是**日前均价的跨日变化**，不是同小时 DA−RT 价差。

从当前正式运行时因子库核对的系数：

两工件残差样本分别 38、34 个，`label_cutoff=2026-09-07`；对应信号工件版本为 `d1-weather-rolling-residual-v1`、`d3-weather-rolling-residual-v1`。本次读取的运行时 `因子库.md` SHA-256 为 `9912A59529615FBD3115F4375543C006C78C3054B09B7749634068DE91D60AC3`。这些是某版工件的系数，不是所有月份恒定、也不是指标贡献的因果解释。`price_signal_logic.py` 通过 `factor_library().require(("gx_calibration_d1", "gx_calibration_d3"))` 获取当前版本。

核心代码结构：

```python
artifact = calibration_d1 if lead == 1 else calibration_d3
base = origin if lead == 1 else target - timedelta(days=3)
mu = artifact['intercept'] + sum(
    coef * (weather[target][field] - weather[base][field]) / reference[field]['std']
    for field, coef in artifact['coefficients'].items()
)
```

其中天气输入必须是起报时可得到的预报快照；复盘不能拿事后实况重新计算当时信号。

## 3. 残差概率与提示

冻结历史滚动样本外残差 `e_i` 加到预期变化 `μ` 上，形成候选结果。金额阈值为 `τ`，提示概率门槛为 `g`：

```text
p_up   = [Σ_i 1(μ+e_i>τ)+0.5] / (n+1.5)
p_down = [Σ_i 1(μ+e_i<−τ)+0.5] / (n+1.5)
大涨：p_up≥g 且 μ≥τ；大跌：p_down≥g 且 μ≤−τ；否则不提示。
```

源码 `price_signal_logic.py:17-51,58-90` 会先检查 `label_cutoff < 起报日期`，避免用未来标签刷新历史页面；`price_model.py:181-184` 也约束方向与点预测同号。概率是经验校准，并不直接等于“69.1% 实盘命中率”。

## 4. 事前快照到事后准确率

`price_signal_review.py:274-315` 保存起报时信号，复盘时 `:317-360` 仅选满足以下条件的样本：分析型、非旧口径、生成日期早于目标日、价格数据截止早于目标日、系数标签截止早于起报日；同一基准日和提前期只取**最早**合格分析，且目标与基准日实际日前价都须齐全。

网页的**累计情景准确率**另由 `signal_ledger.py:select_review_records` 提供：按目标日 D 取 D−3 当天原预测，自动任务优先，无自动任务才取手动分析，同类取最后一次；`signal-ledger.js` 只把已验证的急涨/急跌方向计入分母。2026-10-15 只读运行仓库复算为 **12/15 = 80.0%**。这是当前页面应展示的累计值，与下面严格事前有效首份提示的 **38/55 = 69.1%** 不可互换。若写领导汇报，明确选用“台账累计情景”或“研究提示复核”，附各自分母。

实际事件按 `ΔP_actual` 与同次 `τ` 比较。提示命中率为 `已命中的大涨/大跌提示数 ÷ 已复盘的大涨/大跌提示数`；不提示不进分母，但应单列覆盖率。2026-10-15 用数据集 `PRICE-a2685d0b2ff8dfefbc669fa3` 和上述 D+1/D+3 信号工件版本只读复算，目标日 2026-09-09—10-15 的已复盘合格提示为 **38/55 = 69.1%**。其中 9 月 **9/9**，样本过小，不宜单独宣称长期稳定准确率。

## 5. 不同的同小时申报收益

日前申报另用 `S(h)=P_DA(h)−P_RT(h)`：`S<0` 的多报方向、`S>0` 的少报方向才与实际相符。`declaration_export.py:260-400` 依时段结合天气和预测价格；`price_signal_review.py:35-164` 复盘事前建议。2026 年 9 月是 **226/304 = 74.3%** 方向命中、**29.4%** 理论价差机会捕获；与上面的 **69.1%** 价格变化信号不是同一任务或分母。缺成交电量与结算数据时不能换算人民币利润。
